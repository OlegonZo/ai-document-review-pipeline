# Reversal Radar — сигналы разворота по перпу (HYPE и другие)

Радар отвечает на один вопрос: **что сейчас подтверждено данными — разворот или продолжение**, и где сценарий считается сломанным.

Он не предсказывает цену. Прогноз со 100% точностью невозможен; вместо него радар считает набор проверяемых условий, складывает их с весами и выдаёт счёт от −100 (разворот вниз) до +100 (пробой вверх) плюс план на оба исхода с точками инвалидации.

## Что именно проверяется

| Сигнал | Что смотрит | Куда трактуется |
| --- | --- | --- |
| `level_reaction` | последняя свеча у уровня: прокол с закрытием обратно, чистое закрытие за уровень, удержание после пробоя | отказ → вниз, пробой на объёме → вверх |
| `level_fatigue` | несколько подходов к одному уровню подряд | падающий объём подходов → уровень держится |
| `volume_confirmation` | наклон объёма против движения цены за 10 свечей | рост на затухающем объёме → вниз |
| `volume_spike` | z-оценка объёма последней свечи | крупная красная свеча на объёме → вниз |
| `rsi_divergence` | два разнесённых экстремума цены и RSI на каждом ТФ | новый хай без нового хая RSI → вниз |
| `rsi_extreme` | RSI > 72 / < 28 | перегрев → вниз, перепроданность → вверх |
| `funding` | ставка финансирования в годовом выражении | сильно положительная → перегруз лонгов |
| `open_interest` | OI против цены между снимками | OI растёт, цена стоит → ловушка |
| `book_pressure` | плотность заявок в полосе ±0.5% от середины стакана | стена на продажу → вниз |
| `mtf_alignment` | согласие 15m / 1h / 4h / 1d по EMA20-EMA50 | совпадение ТФ усиливает сценарий |

Вес каждого сигнала задаётся в `reversal_radar/config.py`. Дивергенция на 4Ч весит больше, чем на 15м. Сигнал без данных (нет стакана, нет истории OI) не подставляет ноль молча — он выпадает из знаменателя, а в отчёте появляется строка в разделе «Ограничения данных». Поле `coverage` показывает, какая доля весов реально была обеспечена данными.

## Быстрый старт

```bash
pip install -r requirements.txt

# разовый отчёт по HYPE с уровнем 83.40
python -m reversal_radar --coin HYPE --level 83.40 report

# то же в JSON (для скриптов и виджетов)
python -m reversal_radar --coin HYPE --level 83.40 report --json

# уровни, найденные автоматически по пивотам
python -m reversal_radar --coin HYPE levels

# демо без сети: синтетический сценарий затухания у уровня
python -m reversal_radar --demo exhaustion --level 83.40 report
python -m reversal_radar --demo breakout --level 83.40 report
```

Данные берутся из публичного `info`-эндпоинта Hyperliquid (`https://api.hyperliquid.xyz/info`): свечи, funding, open interest, стакан. Ключи и подпись не нужны, аккаунт не требуется.

## Наблюдение и алерты

```bash
# опрашивать раз в 3 минуты и писать в консоль
python -m reversal_radar --coin HYPE --level 83.40 watch --interval 180
```

Алерт уходит не на каждый опрос, а когда меняется картина:

- первый значимый сигнал после запуска;
- смена состояния (например, `undecided` → `weakening`);
- подтверждённый разворот или пробой — такой алерт пробивает паузу между сообщениями;
- сдвиг счёта на 15+ пунктов после паузы (`alert_cooldown_seconds`, по умолчанию 30 минут).

Каналы включаются переменными окружения; консоль работает всегда:

```bash
export RADAR_TELEGRAM_TOKEN=123456:AA...   # токен от @BotFather
export RADAR_TELEGRAM_CHAT_ID=123456789    # свой id можно узнать у @userinfobot
export RADAR_WEBHOOK_URL=https://n8n.example/webhook/radar-alert  # необязательно
```

## Телеграм-бот

```bash
python -m reversal_radar --coin HYPE --level 83.40 bot --interval 180
```

Команды в чате: `/status`, `/level 83.40`, `/level auto`, `/coin HYPE`, `/watch on|off`, `/settings`, `/help`. Бот отвечает только в чат с указанным `RADAR_TELEGRAM_CHAT_ID` — чужие сообщения игнорируются.

## Виджет

```bash
python -m reversal_radar --coin HYPE serve --port 8100
# открыть http://127.0.0.1:8100
```

Одна самодостаточная страница без внешних скриптов: шкала счёта, список сигналов с вкладом каждого, чипы таймфреймов, план на оба исхода, раздел ограничений. Поля «монета» и «уровень» меняются прямо на странице, интервал обновления — от 30 секунд до ручного.

JSON API: `GET /api/report?coin=HYPE&level=83.40`, `GET /api/history?coin=HYPE`, `GET /health`. Ответ кэшируется на 30 секунд, чтобы обновление страницы не било по бирже.

## Docker

```bash
export RADAR_TELEGRAM_TOKEN=...; export RADAR_TELEGRAM_CHAT_ID=...
docker compose -f docker-compose.radar.yml up --build
```

Поднимаются виджет на `:8100` и бот с автоперезапуском; история снимков лежит в томе `radar_data`, чтобы динамика OI не терялась между перезапусками.

## Что можно и чего нельзя ждать

- Радар видит рынок только в момент опроса. Между опросами он ничего не знает.
- История OI появляется со второго снимка: до этого сигнал честно помечен как «нет данных».
- Незакрытая свеча в анализ не берётся — её объём и закрытие ещё изменятся.
- Синтетические сценарии (`--demo`) нужны для проверки логики и тестов, а не для оценки доходности.
- Никакой сигнал не даёт вероятности исхода. Смысл отчёта — заранее знать, что подтвердит каждый сценарий и где он сломан.

## Как расширить

- Новый источник данных: класс с методом `fetch(coin, timeframes, limit) -> MarketSnapshot` (см. `sources/base.py`), дальше он подставляется в `Watcher` или в `api.configure`.
- Новый сигнал: чистая функция в `signals.py`, возвращающая `Signal`, плюс вес в `DEFAULT_WEIGHTS` и вызов в `engine.analyse`.
- Пороги состояний и период опроса — в `RadarConfig` или через переменные `RADAR_*`.

## Тесты

```bash
python -m unittest discover -s tests -v
```

Тесты работают без сети: сигналы проверяются на построенных вручную свечах, сквозной сценарий — на детерминированной синтетике.
